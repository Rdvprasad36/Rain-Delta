Methods & Limits

How the numbers are computed, what they mean, and what they cannot tell you.

🌐 Data Sources

MonsoonDelta uses ECMWF open data — freely available via data.ecmwf.int under the CC BY 4.0 licence. No API key is required. Two models are used:

  • IFS (Integrated Forecasting System) — class=od, stream=oper, type=fc. Run 4× daily at 00/06/12/18 UTC. 0.25° global grid.
  • AIFS Single (AI-based IFS) — model=aifs-single, stream=oper, type=fc. Run 2× daily at 00/12 UTC. 0.25° global grid. Steps 6-hourly to 360 h.

Parameter: tp (total precipitation, paramId 228 for IFS, 228228 for AIFS). Units are read from the GRIB units key; unknown units raise an error and halt ingestion.

🔢 Accumulation and 6-Hour Totals

tp is a cumulative field: it records the total precipitation since the forecast start (step 0). To get a 6-hour window total:

W(s) = tp(s) − tp(s − 6h) [mm]
Special case: W(6) = tp(6) since tp(0) = 0

Unit conversion

  • IFS: units = metres → multiply by 1000 to get mm.
  • AIFS: units = kg m⁻² → 1 kg m⁻² of liquid water = 1 mm depth (no conversion needed).

Hand-checked example (from PRD §2.2):

IFS: tp(12h) = 0.002 m = 2.0 mm; tp(18h) = 0.005 m = 5.0 mm
W(18h) = 5.0 − 2.0 = 3.0 mm ✓

AIFS: tp(12h) = 2.0 kg m⁻²; tp(18h) = 5.0 kg m⁻²
W(18h) = 5.0 − 2.0 = 3.0 mm ✓

Tiny negative differences (> −0.05 mm) caused by GRIB packing are clamped to 0 and logged. Larger negatives indicate a data problem and halt processing with an error.

📈 Forecast Revision

Fix a valid 6-hour window ending at time T. Each model run r that covers T (i.e. its lead time is long enough) gives a 6-hour total A_r(T). We collect the last N runs (default 6), skipping any that do not cover T.

Latest change = A_latest − A_previous [mm]
Range = max(A_r) − min(A_r) [mm]
Direction = "up" | "down" | "steady" (|change| < 0.5 mm)

Hand-checked example (PRD §2.3):

Runs 00Z → 06Z → 12Z: 4.0, 10.0, 7.0 mm
Latest change = 7.0 − 10.0 = −3.0 mm (down) ✓
Range = 10.0 − 4.0 = 6.0 mm ✓

A run that does not reach the target window is skipped; it is never zero-filled.

🔀 Model Disagreement

For the same valid window, using the most recent run from each model:

D = IFS_mm − AIFS_mm [mm]
Positive D → IFS is wetter. Negative D → AIFS is wetter.

Percentage difference is not shown when both models produce less than 1 mm (the ratio becomes misleading for tiny values).

Hand-checked example (PRD §2.4):

IFS = 7.0 mm, AIFS = 3.0 mm → D = +4.0 mm (IFS wetter) ✓

📍 Point Extraction

The displayed value for a location is the area mean of the 4 surrounding 0.25° grid cells (bilinear-style), not a single nearest cell. This reduces single-cell noise for coastal locations like Visakhapatnam (~17.7°N, 83.2°E).

⚠️ Known Limits

  • Grid resolution is 0.25° (~28 km). Local terrain, urban effects, and coastal gradients are not captured.
  • IFS and AIFS are global models; they do not replace high-resolution local or convective-scale forecasts.
  • ECMWF retains open-data files for only a few days. MonsoonDelta stores the last 14 days internally, but older history is not available.
  • AIFS is an experimental AI-based model. Its uncertainty characteristics differ from IFS and are not fully understood.
  • This service does not provide ensemble probability estimates.
  • Units and file availability were verified from ECMWF documentation; some details may change with new model versions.
